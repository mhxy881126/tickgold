WORKBENCH REVAMP · 4 PROPOSALS

卡片工作台改版 · 4 版方案对比

针对你提的两个痛点——① 卡片自定义编排不好用、② 菜单功能 / 卡片切换不好用， 我对照当前实现（顶栏 + 指数条 + Mega 导航 + 场景模板 + 时段 tabs 共 5 层横条、main/side 两分区粗粒度拖拽、聚焦态右侧小 rail） 出了 4 版差异化高保真原型。每版都能直接点开看完整效果。

痛点 1 · 卡片编排

只有 main / side 两分区，落点粗

拖拽只能落到左 7/12 或右 5/12，before/after 两档；要真正自由摆放必须进"布局"菜单切模式，操作深。

痛点 2 · 菜单层级

5 层横条堆叠，语义重叠

顶栏 / 指数条 / Mega 功能 tabs / 场景模板 chips / 时段 tabs——垂直吃掉 ~180px，功能、场景、时段三组控件职责模糊。

痛点 3 · 卡片切换

聚焦态 rail 又小又硬切

右侧 rail 只有文字小条、无卡片预览、无键盘切换提示，多卡时找不到当前在哪张。

RECOMMENDED

方案 A · 左侧 Dock + 底部 Tab 流

VSCode / Linear 风

把 Mega 横条收成左侧 56px 竖排 icon dock，场景/时段合并为顶栏右侧分段控件。

  • 菜单：分类常驻左侧，点击即出面板，告别悬停 mega
  • 编排：保留主区网格，一键切换"布局模式"按钮上移到场景行
  • 切换：底部 Chrome 风 Tab 流，可拖排序、中键关闭、Ctrl+数字直达
适合：大多数老用户，改动最平滑，学习成本最低

方案 B · 超级顶栏 + 槽位吸附

紧凑融合风

5 层横条压成 1 条 44px 超级顶栏，垂直省出 ~110px 全部还给图表。

  • 菜单：指数 ticker + 功能 tabs + 场景 chips 全在一条
  • 编排：拖卡片即显 6 个虚线槽位（左大/右列/底部通栏），所见即所得
  • 切换：右侧 rail 升级带卡片缩略图，←/→ 键淡入滑动
适合：屏幕小、想最大化看盘面积的用户
MOST FLEXIBLE

方案 C · 无限画布 + 悬浮工具栏

Figma / Notion 风

彻底去掉横条，卡片像 Figma 一样自由浮在点格画布上，可叠放、可缩放。

  • 菜单：点 + 出环形 radial 菜单，围绕光标展开，手不离鼠标
  • 编排：绝对自由布局 + 右下角小地图全局导航 + 视图书签存场景
  • 切换：底部 macOS Dock 风切换条，hover 放大预览
适合：重度 DIY 用户、多屏拼接，但学习成本最高
POWER USERS

方案 D · 导航树 + Splitter 分栏

通达信 / Bloomberg 风

左侧 180px 常驻两级功能树，主区像 VSCode 一样自由 splitter 分栏。

  • 菜单：分类→功能两级树常驻，不用悬停，一眼找得到
  • 编排：gutter 横竖拖拽分栏，自己画比例，每栏独立滚动
  • 切换：每栏 Chrome 风 Tab，中键关闭、Ctrl+Tab 切换
适合：专业交易员、卡片极多的资深用户

💡 推荐路径

主推 A 作为下一代工作台主干：它在"菜单好找、编排够用、切换顺手"三者间最均衡， 且对现有 App.vue / LayoutMenu / useWorkbench 改动最小——Mega 导航改成 dock、底部加 Tab 流、 场景 chips 合并进顶栏右侧分段，2-3 周可落地。

B 的"槽位吸附"编排体验建议作为独立增强吸收进 A：不管最终布局形态如何， 拖拽时显示 6 个虚线槽位这件事本身就是痛点 1 的直接解药，值得单独做。

C / D 作为远期方向：C 适合未来做大屏/多屏拼接模式，D 适合给专业用户做"交易员模式"开关。
