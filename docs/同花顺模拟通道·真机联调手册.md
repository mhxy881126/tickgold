# 同花顺模拟通道 · 真机联调手册（P3）

> 适用版本：TickGold v3.1.1 及以上
> 通道名称：**同花顺模拟 · 桌面自动化**（设置 → 券商交易 → 第三个模式卡）
> 定位：用桌面自动化（pywinauto）操控本机**同花顺模拟炒股**客户端，**虚拟资金练手，全程不碰真钱**，为后续真实通道（P4）铺路。

---

## 0. 先看懂安全边界（务必先读）

| 项目 | 说明 |
| --- | --- |
| 下单对象 | 同花顺**模拟炒股**客户端（虚拟资金账户），**不是真实委托** |
| 真钱风险 | 本通道在「模拟交易」开关开启时，**不会提交任何真实委托**，没有任何资金风险 |
| 实盘开关 | 同花顺模拟通道**不显示实盘开关**（实盘卡片显示"无需实盘开关"）。真实通道（关闭「模拟交易」）为后续版本开放，当前不放开 |
| 两道保险 | ① `dry-run 空跑` 开关：连真实客户端都不碰，纯内存模拟；② `自动确认` 开关：关闭后每笔都要人工在「截图确认桥」点确认才会真正下单 |
| 强制规则 | 一旦关闭「模拟交易」（即真实通道），后端强制 `自动确认=false`，不允许无人值守真实下单 |

**建议上线路径（三阶段，逐级放开）：**

1. **阶段一：dry-run 空跑**——两个开关都开，不连客户端，验证 TickGold 全链路。
2. **阶段二：真机半自动**——关掉 dry-run、保留模拟交易、**关掉自动确认**，每笔弹截图人工核对后才在同花顺模拟客户端点确定。
3. **阶段三：真机全自动**——阶段二稳定后，再打开自动确认（仅模拟环境允许）。

---

## 1. 环境准备

### 1.1 安装 Python（真机模式需要）

- 推荐 **Python 3.10 ~ 3.12（64 位）**。暂不建议 3.13（pywinauto 桌面控件兼容性）。
- 安装时勾选 **Add Python to PATH**。
- 安装后打开 PowerShell 验证：

```powershell
python --version
pip --version
```

> 阶段一（dry-run 空跑）只用 Python 标准库，**不装任何第三方包也能跑**；阶段二/三才需要下面的依赖。

### 1.2 安装自动化依赖（阶段二/三）

```powershell
pip install pywinauto pyautogui pillow
```

| 依赖 | 用途 |
| --- | --- |
| pywinauto | 连接/操控同花顺窗口、读写下单输入框、点按钮（win32 后端） |
| pyautogui | 控件定位失败时的图像匹配兜底（按钮截图点击） |
| pillow | 下单前窗口截图回传到「截图确认桥」 |

### 1.3 准备并登录同花顺模拟炒股

1. 打开同花顺免费客户端，进入**委托 / 交易**，选择**模拟炒股**（部分版本为独立的模拟交易下单程序 `xiadan.exe`）。
2. 用模拟账号登录，**确认能看到买入 / 卖出 / 撤单界面且账户已登录**。
3. 把交易窗口保持在**固定位置、固定大小、100% 缩放**（自动化对窗口位置和分辨率敏感，移动/缩放会触发窗口保护自动暂停）。
4. 记下下单程序的完整路径（例如 `D:\xxx\simulator\xiadan.exe`），后面填到「同花顺客户端路径」。留空则按窗口标题自动探测。

## 2. 在 TickGold 里配置并连接

打开 **设置 → 券商交易 → 选择「同花顺模拟」模式卡**。

### 2.1 客户端参数

| 字段 | 填什么 |
| --- | --- |
| **Python 路径** | `python.exe`（已在 PATH 即可这样填）；否则填完整路径，如 `C:\Python312\python.exe` |
| **同花顺客户端路径（可选）** | 模拟交易下单程序（如 `xiadan.exe`）的完整路径；留空则按窗口标题自动探测 |
| **控件模板目录（可选）** | `selectors.json` 所在目录（见第 4 节）；留空使用脚本内置的启发式定位 |
| **最小操作间隔（毫秒）** | 相邻两笔下单的限速，默认 `1200`，最小 `300`。**不建议调小**，防止过快误操作 |

### 2.2 三个开关

| 开关 | 含义 | 阶段一 | 阶段二 | 阶段三 |
| --- | --- | --- | --- | --- |
| **模拟交易（虚拟资金）** | 走同花顺模拟炒股，不碰真钱 | 开 | 开 | 开 |
| **dry-run 空跑（不操控客户端）** | 开：sidecar 内置虚拟账户，连客户端都不连；关：才真正操控同花顺 | **开** | **关** | **关** |
| **自动确认（全自动）** | 开：填单后自动点确认；关：每笔弹「截图确认桥」人工核对 | 开 | **关** | 开 |

> 「自动确认」开关在非模拟环境（真实通道）会被禁用并强制关闭——这是硬性安全设计，无法绕过。

### 2.3 连接与自检

1. 点 **保存配置**，再点 **连接通道**（连接后约 2 秒会自动拉一次自检；也可随时点 **刷新自检**）。
2. 顶部状态条：未连接 → `同花顺模拟 · 已连接`。
3. **连接自检**面板逐项给出 ✓/✗，标题右侧显示模式：`ths · dry-run 空跑 / 模拟交易 / 真实通道 · auto/semi`。

**自检项含义与处理：**

| 检查项 | 通过条件 | 红叉怎么办 |
| --- | --- | --- |
| `python` | Python 可启动 | 检查 Python 路径 / 重装 Python |
| `pywinauto` | 真机模式能 import | `pip install pywinauto`（dry-run 下显示"无需 pywinauto"，属正常） |
| `client_window` | 找到交易窗口 | 先启动并登录同花顺模拟交易；或填准「客户端路径」 |
| `login` | 未检测到登录按钮 | 在客户端完成模拟炒股登录 |
| `templates` | 找到 `selectors.json` | 首次真机建议按第 4 节录制；没有也能用启发式定位（自检会给 warning） |
| `resolution` | 能读到窗口尺寸 | 确认窗口正常显示、未最小化 |

阶段一（dry-run）所有检查项都应显示通过。

## 3. 两种下单模式怎么用

### 3.1 半自动（推荐真机首用，关闭「自动确认」）

1. TickGold 产生买入/卖出信号并确认后，sidecar 自动切到同花顺买/卖面板（F1/F2）、填好代码、价格、数量。
2. 填单后**先截图回传**，TickGold 弹出「**下单前核对 · 同花顺模拟**」浮层，显示：
   - 方向（买入红色 / 卖出绿色）、证券代码、价格、数量、金额、`模拟盘` 标记；
   - 同花顺下单窗口的实时截图。
3. 你逐项核对截图与上方数据是否一致：
   - 点 **核对无误 · 确认下单** → sidecar 才会在客户端点最终确认；
   - 点 **取消委托** → 撤掉该笔，不下单。
4. 半自动等待超时：**真机 300 秒、dry-run 120 秒**，超时未确认按取消处理。

### 3.2 全自动（打开「自动确认」，仅模拟环境）

填单、读回比对通过后自动点确认，不再逐笔人工点。**请在阶段二半自动稳定运行后再开启**，并保留「最小操作间隔」限速。

## 4. 录制控件模板 selectors.json（真机校准，重要）

不同券商/版本的同花顺下单窗口控件 `auto_id` 不同，**首次真机强烈建议录制**，否则使用"Edit 顺序 + 按钮标题正则"的启发式定位，可能在个别版本上失效。

### 4.1 模板文件位置

在「控件模板目录」指向的文件夹里放一个 `selectors.json`（目录名自取，例如 `D:\tickgold-templates\ths\selectors.json`）。

### 4.2 模板结构

```json
{
  "window_title_re": "同花顺|模拟炒股|网上股票交易|交易系统|委托",
  "code_edit":  { "auto_id": "1001" },
  "price_edit": { "auto_id": "1002" },
  "vol_edit":   { "auto_id": "1003" },
  "template_buy": "buy.png",
  "template_confirm": "confirm.png",
  "asset_table":    { "auto_id": "2001" },
  "position_table": { "auto_id": "2002" }
}
```

| 键 | 含义 | 不填时 |
| --- | --- | --- |
| `window_title_re` | 交易窗口标题正则（用于找到窗口） | 用内置默认正则 |
| `code_edit` / `price_edit` / `vol_edit` | 代码 / 价格 / 数量输入框，值为 `{"auto_id": "..."}` | 按 Edit 控件顺序 0/1/2 启发式定位 |
| `template_buy` / `template_confirm` | 买入/确认按钮的**截图模板文件名**（放在同目录，png），pywinauto 找不到按钮时用图像匹配兜底 | 无图像兜底 |
| `asset_table` / `position_table` | 资产/持仓表格控件（真机表格解析，首版预留） | 资产/持仓查询返回中文提示，不编造数据 |

### 4.3 怎么拿到 auto_id

登录并打开同花顺模拟交易下单窗口后，运行：

```python
# save as inspect_ths.py
from pywinauto import Application
app = Application(backend="win32").connect(title_re="同花顺|模拟炒股|网上股票交易|交易系统|委托")
win = app.window(title_re="同花顺|模拟炒股|网上股票交易|交易系统|委托")
win.print_control_identifiers(depth=6)
```

```powershell
python inspect_ths.py
```

输出里找到代码、价格、数量三个 `Edit` 控件的 `auto_id`（形如 `1001`），以及资产/持仓表格的 `auto_id`，填入 `selectors.json`。

### 4.4 按钮图像模板（可选兜底）

用截图工具把下单窗口的「买入」「确认下单/确定」按钮各截一张小图（只含按钮本身，png），命名为 `buy.png`、`confirm.png`，与 `selectors.json` 放同一目录。按钮标题正则匹配不到时会自动改为图像匹配点击。

## 5. 热键与下单流程（sidecar 内部约定）

| 操作 | 按键 / 步骤 |
| --- | --- |
| 切买入面板 | `F1` |
| 切卖出面板 | `F2` |
| 撤单面板 | `F3` |
| 代码输入 | 下单框输 **6 位裸码**（应用传 `600519.SH`，sidecar 自动去后缀成 `600519`） |
| 填单顺序 | 代码 → 价格 → 数量，随后**读回三个字段逐字段比对** |
| 最终确认 | 半自动：人工在确认桥放行；全自动：自动点「买入/卖出/确认下单/确定」 |

**内置护栏：**

- 代码必须为 6 位数字；数量必须为 100 的正整数倍；价格必须 > 0；
- 相邻下单限速（默认 1200ms）；
- 填单后读回代码/价格/数量，与期望不一致立即中止，不提交；
- 资金不足（买入）/ 持仓不足（卖出）在**填单前预校验**直接拒绝，不产生假提交；
- 窗口保护：窗口关闭、尺寸/位置变化、模态弹窗遮挡、未登录时立即暂停，避免误操作。

## 6. 高级：命令行手动跑 dry-run（不开 TickGold 也能验证 sidecar）

在 `src-tauri/resources/broker/` 目录下：

```powershell
# 全自动 dry-run（虚拟账户 100 万，不连客户端）
python sidecar_client.py --vendor ths --sim --dry-run --auto-confirm
```

进程通过 stdin 收 NDJSON 请求、stdout 回 NDJSON 事件。另开一个场景：程序启动后在窗口里直接粘贴一行请求回车：

```json
{"id":"1","method":"submit","params":{"code":"600519.SH","side":"BUY","price":1688.5,"vol":100,"client_order_id":"t1"}}
```

常用方法：`submit` / `cancel` / `confirm` / `reject` / `query_asset` / `query_position` / `heartbeat` / `kill`。

半自动（去掉 `--auto-confirm`）时，下单后会先发 `screenshot` 并挂起，需要再发：

```json
{"id":"2","method":"confirm","params":{"client_order_id":"t1"}}
```

拒绝则把 `confirm` 换成 `reject`。

dry-run 费用口径（自洽，用于勾稽）：佣金万 1、最低 5 元；卖出另收印花税千 1。

## 7. 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 自检 `client_window` 红叉 | 未启动/未登录模拟交易；或窗口标题不在正则内（用第 4.3 脚本确认真实标题，改 `window_title_re`） |
| 自检 `login` 红叉 | 客户端停在登录页，先在客户端登录模拟炒股 |
| 自检 `pywinauto` 红叉 | 未装依赖或 Python 版本过新；`pip install pywinauto pyautogui pillow`，建议 Python 3.10–3.12 |
| 提示"定位下单输入框失败" | 该版本控件顺序不同，必须录制 `selectors.json` 的三个 `*_edit` |
| 提示"代码/价格/数量读回不一致"并中止 | 读回保护拦下了填单偏差，未下单；检查客户端是否有价格笼子/最小单位弹窗、模板是否错位 |
| 提示"窗口尺寸/位置变化，已暂停" | 窗口被移动/缩放/改了分辨率，重新点「连接通道」即可 |
| 提示"检测到弹窗遮挡" | 先在同花顺客户端处理掉错误/提示/风险弹窗 |
| 确认桥迟迟不弹 | 确认当前是半自动（自动确认关）；看「刷新自检」是否为 `semi` 模式 |
| 资产/持仓查询只回中文提示 | 真机表格解析为首版预留，需在 `selectors.json` 配 `asset_table`/`position_table`（见第 8 节） |
| 连接后立刻断开 | 看 sidecar 自检明细；多数是 Python 路径或依赖问题，先跑第 6 节 dry-run 排除 |

## 8. 首版固有限制（真机，已知并明确告知）

- **成交回报**：真机模式点击确认后，是否成交以客户端「委托查询 / 成交列表」为准，sidecar 首版不自动解析成交（dry-run 才是提交即成交）。
- **撤单**：目前自动打开撤单面板（F3），具体勾选哪笔委托、点撤单按钮需要在 `selectors.json` 进一步校准。
- **资产 / 持仓读取**：真机表格解析预留，未配置 `asset_table` / `position_table` 时返回中文提示而**不会编造数字**。
- **厂商**：当前为同花顺（`--vendor ths`）；东财（`eastmoney`）为占位，未实现。
- **缩放/分辨率**：真机自动化要求窗口位置、大小、系统缩放固定，变化即触发窗口保护。

## 9. 从模拟走向真实（P4 预告，当前未开放）

- 关闭「模拟交易」即进入真实通道语义，后端会**强制关闭自动确认**、并要求实盘开关与单笔金额上限（当前 UI 仅 QMT 通道放开，同花顺真实通道在 P4 开放）。
- 真实通道上线前必须：完成本手册第 4 节模板校准、阶段二半自动稳定运行、明确单笔金额上限与风控阈值。
- **任何时候，真实资金下单都应先走半自动人工确认，确认无误后再考虑自动化。**
