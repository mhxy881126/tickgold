P0 · 立即整改 AI 输出「建议化」——触碰荐股软件红线

依据：《证券法》第120/160条、《证券、期货投资咨询管理暂行办法》、《关于加强对利用"荐股软件"从事证券投资咨询业务监管的暂行规定》第二条——向投资者有偿提供个股投资分析/预测/建议属证券投资咨询业务，须持牌；AI 不豁免资质。

快脑输出 BUY / SELL 四分类 + 概率（操作建议）
src-tauri/src/ai/fastbrain.rs（RuleBrain + LLM 双模）
系统提示词写「你是A股短线交易助手…给出操作建议」，输出 BUY/SELL/HOLD/NO_BUY 标签与置信度；前端以信号卡、灵动岛直接展示「买入/卖出」信号。
改法：prompt 改为「依据结构化数据做特征归纳，不做方向性结论」；标签语义改为中性观察态（如 watch_up / watch_down / hold / calm），前端文案同步去掉「买入/卖出」字样，改为「上涨/下跌特征概率」，信号桥文案不再用「BUY/SELL 信号」。
监管依据：《荐股软件监管暂行规定》第二条；证监会风险提示「有偿提供个股投资分析、预测或建议即非法荐股」。
AI 预警推荐：以「推荐/策略师」身份输出个股预警规则
src-tauri/src/ai/commentary.rs（SYSTEM_ALERT）
prompt「你是 A 股预警策略师…推荐应该设置的预警规则…推荐理由」，对具体个股给出操作导向建议。
改法：身份改为「行情特征整理助手」；「推荐」改「提示可监测的规则模板」；「推荐理由」改「监测要点（仅描述波动/量能事实）」；取消优先级 high/medium/low 的「重要度」暗示。
监管依据：同 P0-1；预警推送对个股的定向操作提示属变相荐股（证监会「付费打赏变相荐股」案例）。
作战计划：字段含「操作建议 / 仓位提示 / 满足条件即行动」
src-tauri/src/ai/plan.rs（gen_plan）
计划 JSON 含 action:「操作建议」、positionHint:「仓位提示」、trigger=「满足条件即行动」，虽带「不构成投资建议」铁律，但字段语义即个股操作建议 + 仓位建议。
改法：字段重命名：action→「关注要点」、positionHint→「风险提示」、trigger→「需人工确认的观察条件」；prompt 铁律强化「仅输出事实与风险提示，不输出买卖/仓位指令」。
监管依据：《证券、期货投资咨询管理暂行办法》第3条；个股操作/仓位建议属投资咨询。
慢脑人设：资深短线交易专家 / 买卖信号 / 操作思路
src-tauri/src/ai/agent.rs（SYSTEM_PROMPT）
「资深 A 股短线交易专家」「个股诊断：买卖信号」「策略建议：给出操作思路」——虽有铁律与免责（这部分保留），但人设与能力描述带「建议」性质。
改法：人设改为「行情数据整理与事实核查助手」；「买卖信号」→「行情特征（量价/资金/涨停结构）」；「给出操作思路」→「梳理可用信息，不提供买卖建议」；保留「不预测涨跌、末尾免责」铁律。
监管依据：证券投资咨询资质要求；网信办+证监会 AI 荐股整治口径。

P1 · 短期整改 自动交易链路——程序化交易监管

依据：《证券市场程序化交易管理规定（试行）》（证监会公告〔2024〕8号，2024-10-08 施行）——通过程序自动生成/下达交易指令即程序化交易，须向交易所报告、接受实时监控与异常交易防控。

QMT 实盘 sidecar 具备真实下单能力
src-tauri/resources/broker/sidecar_qmt.py（order_stock / STOCK_BUY / STOCK_SELL）
已默认锁定（live_enabled=false、live_max_order_amount=0，代码注释「实盘锁定」），但代码能力完整，一旦放开即进入程序化交易监管范围。
改法：保持默认锁定不变；放开前必须：① 提示用户阅读《程序化交易管理规定》并自行向交易所履行报告义务；② 增加「实盘开通需人工二次确认 + 风险告知书」；③ 保留当前最小限额（live_max_order_amount 非 0 才能开）。
✅ 已完成：broker_enable_live 三前置校验（QMT-only / 限额>0 / ack 确认）+ 前端实盘风险告知书含程序化交易报告义务提醒。
监管依据：《程序化交易管理规定（试行）》第二条、第四条；沪深北交易所《程序化交易管理实施细则》。
autoexec「全自动模式」：所有信号直接下单
src-tauri/src/ai/autoexec.rs（full_auto_mode / trade_mode=full）
注释称模拟盘全自动、实盘只 emit 信号，但 full_auto_mode 字段语义是「不人工确认直接下单」，若未来接到实盘即自动程序化交易。
改法：代码级硬隔离：full_auto_mode 与 live_enabled 互斥（full 模式下 live_enabled 强制 false，提交时校验）；前端 UI 明确标注「全自动仅限模拟盘」。
✅ 已完成：autoexec_start / autoexec_set_config 均校验「全自动与实盘互斥」，实盘开启时拒绝启动/保存；设置面板与爬虫面板标注「全自动仅限模拟盘」。
监管依据：《程序化交易管理规定（试行）》；自动下单须报告。
信号桥：AI 信号一键生成下单指令/唤起券商
src/components/SignalBridge.vue（信号桥 + 下单指令模板）
「双脑 BUY/SELL 信号落待确认单…生成下单指令（复制/导出/唤起券商软件）」——把 AI 信号直接转成下单指令，强化「荐股软件→交易」闭环属性。
改法：默认不生成下单指令模板；信号卡只展示「关注提示」，下单指令改为用户手动创建（不自动预填代码/方向）；文案去「信号」改「关注提醒」。
✅ 已完成：确认时默认生成「关注提示」（build_attention_text，不含买卖方向/数量预填）；仅用户配置自定义指令模板后才渲染下单指令；确认按钮与文案同步中性化。
监管依据：荐股软件红线 + 程序化交易（指令由 AI 信号触发）。
capabilities 仍保留 sql:allow-execute（SQL 直执行）
src-tauri/capabilities/default.json
已移除 shell/global-shortcut（好），但「sql:allow-execute」允许前端任意 SQL 写库——若未来接外部内容/插件市场，是注入与越权风险面。
改法：评估收敛为白名单命令（只暴露封装的业务 command），移除前端直连 sql:execute；至少限定 sql 插件只读 select。
✅ 评估完成（保留 allow-execute）：数据库访问已全部收敛于 db/database.ts 单例封装、SQL 全部参数化（无拼接注入点）、库路径 Rust 侧硬编码本地 sqlite:stock-dock.db（无远程/不可信连接串）；移除会破坏 98 处本地写库（预警/日历/模拟交易/策略库）。前置条件：未来接入插件市场/外部数据源/远程库前必须改为 Rust 白名单命令并移除 sql:allow-execute。
✅ 纵深加固：tauri.conf.json 已补严格 CSP（生产 csp + 开发 devCsp，script-src 'self'、connect-src 仅 ipc 与本地，禁止远程脚本注入）。
监管依据：非直接监管红线，属安全纵深；插件/外部数据接入时是关键防线。

P2 · 中期整改 对外呈现与宣传口径

依据：证监会「警惕股市黑嘴」风险提示；收益/胜率承诺式宣传是非法荐股与误导营销的典型特征。

README / 产品文案突出「历史胜率 / 期望收益 / 跟庄统计」
README.md（席位胜率、期望收益、盈亏比等）；EvolutionStats / Performance / DragonTiger 组件
大量「胜率」「期望收益」「跟庄」表述——自用无碍，一旦对外宣传即构成收益诱导。
改法：对外文档改为「历史样本统计」「样本内回测结果，不代表未来收益」；去掉「跟庄」「抓妖」等营销词；组件内统计标注「仅历史样本，非收益承诺」。
✅ 已完成：README 席位/回灌条目改为「席位历史样本统计」「样本内统计，不代表未来收益」，去除「跟庄/胜率/期望收益」营销词；EvolutionStats / Performance / DragonTiger 组件统计文案中性化（胜率→上涨占比、上榜后表现回测→历史样本统计）。
监管依据：证监会风险提示（付费/收益承诺式荐股整治）。
「明日主线 / AI 预测」类方向性输出
src/components/cards/TomorrowMainline.vue；commentary.rs 主线/解读模块
「明日主线」「AI 预测」虽带免责，但预测式标题对 C 端用户构成诱导。
改法：标题改「今日题材热度梳理」「基于今日数据的题材关联归纳」；正文只列事实（涨停家数、板块涨幅、连板梯队），不预测明日。
✅ 已完成：TomorrowMainline 标题改「今日题材热度」，加载/失败/刷新/置信度文案全部去「预测」改「梳理/归纳」，footer 明示「不预测明日行情」。
监管依据：禁止确定性预测/承诺（证监会风险提示）。
数据源合规声明：免费接口仅限个人用途
docs/数据源说明.md（已声明「个人学习与盯盘用途，勿商业转售」）+ Level-2 插件试点
免费接口条款不覆盖商业化转售；L2 数据（十档/逐笔）需持牌或授权，插件「自带 Key 用户自担合规」需在 UI 显式声明。
改法：保留并强化个人用途声明；商业化前必须：① 与数据源洽谈授权或改用持牌数据供应商；② L2 接入页强制展示「数据来源合规声明 + 用户自担」；③ 严禁接入/分发盗版 L2 数据。
✅ 已完成：L2 Key 录入区强制展示「数据合规声明」（持牌/授权要求 + 个人使用 + 不得转售/再分发/商业产品）；MultiCell 十档盘口使用中显示「数据由你自备的授权账号提供，仅供个人使用」。剩余（商业化前）：与数据商洽谈授权或改用持牌供应商。
监管依据：行情数据版权与授权；Level-2 数据持牌要求。
免责声明覆盖不完整（部分入口缺失）
src/components/：SignalBridge、EvolutionStats、DecisionLog、StrategyScan、DragonTiger、ConditionalOrders 等
已 15 处「不构成投资建议」（AiReview/AiAssistant/BattlePlan/TomorrowMainline/NewsDigest/SignalAttribution/IntradayCommentary/RiskDashboard/AlertSuggestion/Performance/Sieve/StrategyProfiles/ThemeLibrary 等），但交易/信号侧部分组件未覆盖。
改法：抽出全局免责组件（ComplianceFooter.vue）统一挂载：信号桥、决策日志、进化统计、战法选股、龙虎榜、条件单、复盘报告导出、回测卡片，统一文案「仅供参考，不构成投资建议，不承诺收益」。
✅ 已完成：新建 ComplianceFooter.vue（「本软件数据与提示仅供参考，不构成任何投资建议，不承诺收益。据此操作风险自担。」），已挂载 8 个组件：SignalBridge / EvolutionStats / DecisionLog / StrategyScan / DragonTiger / ConditionalOrders / ReviewReport / Backtest。
监管依据：风险披露完整性；投顾业务风险揭示要求。
