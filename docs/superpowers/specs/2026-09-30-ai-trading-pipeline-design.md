# AI 智能化交易系统 · 双脑闭环设计（TickGold）

> 状态：设计已确认，待用户复核　|　日期：2026-09-30　|　基线版本：TickGold v1.1.4
>
> 本文把用户提出的「采集 → 分析 → 计划 → 盯盘 → 执行交易 → 回灌」六步 AI 交易流程，
> 细化为可在 TickGold（Tauri 2 + Rust + Vue 3 + SQLite）上落地的架构、模块、数据模型、
> 接口与版本路线。
>
> **重要口径**：本系统模拟盘全自动；实盘仅推送信号、人工确认下单。全程「不构成投资建议」。

---

## 一、背景与决策记录

### 1.1 六步原始需求

1. **采集**：每日收盘采集涨停数据、题材催化剂、上涨逻辑、个股催化、公司情况。
2. **分析**：结合本地认知知识库、互联网行情、催化剂、连板梯队排列/涨停时间/龙虎榜等
   客观数据，按龙头战法 / 1进2战法 / 抄底战法寻找潜龙。
3. **计划**：把分析结论转换为次日作战计划（复盘、交易计划、决策参考）。
4. **盯盘**：实时行情 + 决策文档打包交 Laya 模型做毫秒级买卖决策，随后进入执行。
5. **执行交易**：模拟交易、自动买卖、自主判断买或不买；保留买卖记录、原因与信号。
6. **回灌**：交易结果回灌知识库，完成知识升级。

### 1.2 关键决策（与需求方确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 本轮交付 | 优化后的系统设计 + 功能需求文档（Markdown） |
| 2 | Laya 定位 | ConvAI Innovations 2026-09-18 开源（Apache 2.0）的**非自回归决策模型**，基于 ModernBERT，单次前向约 33ms（T4），输出分类标签 + 概率，不生成文本；支持 pip 本地部署（CUDA / OpenVINO）与微调 |
| 3 | 交易边界 | **模拟盘全自动 + 实盘只出信号人工下单**；架构预留 QMT/Ptrade 接口（顺延至 v2.3 及以后、合规前提满足时） |
| 4 | 时延口径 | **分层**：Laya 推理毫秒级（33–100ms）；免费行情源决策循环秒级（3–5s）；预留 L2/券商 tick 通道 |
| 5 | 采集范围 | 涨停/连板（已有）+ 龙虎榜（已有）+ 快讯（已有）+ **巨潮公告、自建题材库、互动易/上证e互动、研报** |
| 6 | 知识库形态 | **双层**：可计算规则/因子层（Rust 规则引擎）+ 语义向量层（RAG 供生成式 LLM） |
| 7 | 总体方案 | **方案 A：双脑分层闭环**——慢脑做盘后分析/计划/回灌，快脑做盘中决策 |

### 1.3 已选方案：双脑分层闭环（方案 A）

- **慢脑 System 2（生成式 LLM）**：本地 Ollama 或用户自带云端 Key，经 MCP 工具层调用本地
  数据仓，负责采集归因、AI 复盘、计划生成、盘后总结与知识沉淀；分钟级响应可接受。
- **快脑 System 1（Laya）**：本地非自回归分类模型，盘中对「结构化决策包」输出
  BUY / NO_BUY / HOLD / SELL + 概率，33–100ms，不生成文本。
- **双层知识库**：战法条件形式化为因子规则（可复算）；战法讲解/案例/心得入本地向量库。
- **执行**：模拟盘自主买卖；实盘信号推送灵动岛、人工确认。
- **回灌**：T+N 自动标注样本 → 案例入向量库（每日）；批次足够后离线微调 Laya →
  影子模式验证 → 达标才上线（月度）。

被否方案：B（单 LLM 串行，盘中慢、贵、不可微调）；C（纯规则+Laya，复盘质量低）。

### 2.2 六条设计铁律

1. **快慢脑通过「决策文档」解耦**：慢脑盘后生成次日计划（结构化 JSON + 人话版）；
   盯盘引擎只做事实计算与打包；Laya 只对定长结构化决策包分类，不看新闻不读长文。
2. **事实归事实、判断归判断**：涨停时间/连板/封单/龙虎榜/晋级率等客观数字由 Rust
   规则层计算，LLM 不得改写；LLM 结论必须引用事实 ID，界面可点击跳转核验。
3. **时延分层**：推理毫秒级、决策秒级（免费源）；行情通道抽象预留 L2/QMT 推送，
   升级数据源时决策层代码不变。
4. **三战法共用底座**：龙头 / 1进2 / 抄底只是不同战法档案（规则集、因子权重、
   Laya 分类头/实例不同），候选池、盯盘、执行、回灌全部复用。
5. **闭环全自动只在模拟盘**；实盘模式只推信号 + 人工确认。
6. **本地优先**：默认 Ollama 本地模型 + 本地向量库，数据不出本机；云端 Key 为可选项，
   外发内容明示。

## 三、第 1 步 · 采集层（数据资产 + 题材库 + 公司库）

### 3.1 采集调度（Rust Collector）

统一调度器复用现有交易时段判定、HTTP 并发闸门与多源容灾熔断：

| 时段 | 任务 | 频率 |
|---|---|---|
| 盘中 9:30–15:00 | 情绪/指数/板块时序（已有）、短线精灵事件（已有） | 1–5 分钟 |
| 盘中 | 公告增量扫描（巨潮）、互动易/e互动增量、7×24 快讯（已有） | 5 分钟 |
| 15:05 | 涨停池/炸板池定格（已有）、龙虎榜（已有） | 每日 |
| 15:30 | **涨停归因作业**：涨停股→题材映射、催化剂匹配、梯队快照、封单/换手/涨停时间落库 | 每日 |
| 周末 | 题材库校准（成分变更）、研报增量、F10 公司库刷新 | 每周 |

统一采集元数据：`source / source_url / collected_at / content_hash（去重）/ trade_date`。

### 3.2 题材库（核心新建 · 三主表）

- **`theme` 题材档案**：题材名、别名、级别（主线/分支/一日游，分析层动态标注）、
  生命周期（萌芽/发酵/高潮/退潮）、简介、**上涨逻辑链**（慢脑生成，证据引用，版本化）。
- **`theme_stock` 题材成分**：题材 × 股票；角色（龙一/龙二/助攻/跟风，每日按连板高度+
  封单比+涨停时间重算）；加入/退出日期。
- **`catalyst` 催化剂事件库**：类型（政策/行业/公司/订单/业绩/涨价/事件）、标题、
  正文摘要、来源链接、发布时间、影响方向、关联题材、关联个股、**新鲜度衰减分**
  （半衰期：政策 7 天 / 公司公告 3 天 / 盘中事件 1 天）。

**归因三路交叉**：公告/新闻实体识别 → 成分股涨停反推 → 板块共现聚类；慢脑只做合并
确认，归因结果是可审计数据。

### 3.3 公司库与个股催化

- 复用 F10（概况/财务/筹码，已有）；新增 `company_note`：业务标签、产业链位置、
  **历史股性**（连板基因、股性活跃度、年内涨停次数）、机构持仓变动、解禁/质押排雷。
- **个股催化时间线**：催化剂 + 龙虎榜（含席位胜率，已有）+ 涨停记录 = 催化履历。
- 新增采集源：①巨潮公告（已有 AES 签名能力，扩展全市场增量 + 公告分类）；
  ②互动易 / 上证 e 互动（问答增量）；③研报（仅标题/评级/盈利预测，不存 PDF 全文）。

### 3.4 存储分层

- **SQLite**：全部结构化数据 + 已有时序表（永久保留，沿用迁移体系）。
- **本地向量库**（候选 `sqlite-vec`，随安装包零外部依赖；备选 LanceDB）：
  催化剂摘要、上涨逻辑、公告摘要、研报标题、复盘案例向量化，供慢脑 RAG。
  实现备注：若 tauri-plugin-sql 无法加载向量扩展，则由 Rust 端独立 rusqlite 连接
  加载 sqlite-vec，前端业务库不受影响。
- 原始 PDF/网页不落地，只存摘要 + 原文链接（合规、省空间）。

## 四、第 2 步 · 分析层（AI 复盘 · 三战法寻龙）

### 4.1 分析流水线（盘后，慢脑 S2）

```
事实层（Rust 规则引擎，零幻觉）           认知层（慢脑 RAG 推理）
──────────────────────────            ─────────────────────────
①市场环境判定                          ④题材逻辑解读
  情绪温度/涨跌停/炸板率/连板高度          催化剂新鲜度 + 逻辑链质量 +
  成交额/晋级率/昨日溢价                  题材生命周期
②三战法候选池机器初筛                  ⑤个股故事卡
  因子打分 → 每战法 TOP N                催化 + 股性 + 席位 + 技术位，
③相似场景匹配                           全部带证据 ID
  向量库检索历史相似复盘案例
                          ↓
              ⑥复盘报告（结构化 JSON + 人话版）：
                每个候选 = 战法归属/得分/证据/风险/观察优先级
```

铁律：①②③是可复算代码；慢脑只能引用数字、不能改数字。结论附证据引用
（`fact://limitup/2026-10-09/600xxx` 风格），点击直达涨停池/K线/公告原文。

### 4.2 三战法形式化（战法档案 Strategy Profile）

战法以**外置档案**承载（DB/YAML，版本化、可热更新，不写死代码）：

| 战法 | 机器初筛因子（示例，最终以档案配置为准） | 慢脑解读重点 |
|---|---|---|
| **龙头战法** | 题材内连板高度前 2 / 最高板唯一性、封板时间、炸板 0–1 次、封单/流通比、题材发酵-高潮期、知名席位净买、昨日连板溢价为正 | 主线级别（穿越/抱团/补涨）、龙头唯一性、分歧转一致 |
| **1进2战法** | 昨日首板、竞价高开 2–7%、竞价金额/昨日成交比、题材延续性、流通市值适中、早盘量比与承接 | 首板性质、隔夜溢价环境、弱转强概率 |
| **抄底战法** | 强势股回撤 30–50%、缩量企稳、均线/缺口支撑、情绪冰点回升、无利空排雷、RSI/BOLL 超卖（已有指标） | 回撤性质（洗盘/退潮/逻辑破坏）、催化是否仍在、左侧风险 |

因子全部取自本地数据仓（涨停时间/封单/连板/龙虎榜/竞价/F10/技术指标，多数现有代码
已具备）。档案带版本号；权重只能离线评估调整，**禁止模型盘中改参数**。

## 五、第 3 步 · 计划层（分析 → 可执行计划）

### 5.1 计划三层结构

**① 作战总纲（人话）**：市场阶段 + 总仓位上限（发酵期 ≤70%、退潮期 ≤30% 或空仓）、
主线/支线排序、回避方向、关键时间点。

**② 作战指令表（结构化）**：

```json
{
  "plan_id": "P20261009", "trade_date": "2026-10-10",
  "max_position_pct": 70, "max_single_pct": 25,
  "instructions": [{
    "instruction_id": "I001", "symbol": "300xxx", "strategy": "leader",
    "action": "BUY", "priority": "A",
    "trigger_rules": {
      "time_window": ["09:30", "10:00"],
      "auction_gap": [2, 7],
      "min_turnover_rate": 5, "max_pullback_pct": -3,
      "required_theme_rank": 1,
      "forbid_if": ["seal_blast_today", "index_drop_gt_1pct"]
    },
    "position_pct": 20,
    "add_rules": {"condition": "回封涨停", "add_pct": 5},
    "stop_profit": {"rule": "断板次日不反包", "type": "dynamic"},
    "stop_loss": {"pct": -7, "type": "hard"},
    "validity": "2026-10-10",
    "rationale_refs": ["fact://…"]
  }]
}
```

**③ 决策参考（风险预案）**：指数大跌/题材炸群/不达标时的「不买/等/撤」分支，
每只候选写明放弃条件（如「低开超 3% 立即取消」）。

### 5.2 约束

- **计划盘后生成、盘中不可改**；盘中唯一允许的人工动作是禁用某条指令。
- 每条指令的触发条件必须由 Rust 规则引擎**纯客观判定**；Laya 不发明条件，只在
  条件满足后做最终拍板。
- 计划生成后为**待确认**：AI 作战计划卡逐条批准/删除；默认每晚 20:00 前未确认则
  全部不生效（设置可改自动批准，仅限模拟盘）。
- 计划状态机：`draft → approved → executed / expired / cancelled`；事后对照实际行情
  统计计划命中率（买点后 T+1/T+3 表现），作为回灌输入。

## 六、第 4 步 · 盯盘层（盯盘引擎 + 决策包 + Laya）

### 6.1 盯盘引擎（Rust，5 秒主循环）

盯盘对象 = 已批准指令股 + 持仓股。每轮：

1. 行情快照（东财/腾讯，已有容灾）；
2. 计划触发条件计算（竞价缺口/换手/涨速/量比/板块排名/封炸板边沿，复用规则引擎）；
3. 实时因子（距涨停价%、封单/流通比、分时回撤、委比、大单净流入、题材盘中排名变化）；
4. 上下文压缩（情绪、指数、同题材同伴、持仓敞口）；
5. 条件未满足静默；条件满足组装决策包 → Laya → 出决策。

```json
    "hist_limit_up_120d": 9, "float_mv_log": 22.6
  },
  "short_text": "题材龙一/2连板/09:35封板/炸0/知名席位净买/政策催化第1日",
  "trigger_snapshot": {"matched_rules": ["gap_ok", "turnover_ok"], "forbid_hit": []}
}
```

约 30–40 个因子，全部来自本地数据仓；`short_text` 模板拼接（不让 LLM 现场写，
保证分布稳定）。`schema_version` 固定字段顺序——线上特征工程与微调训练一致性的关键。

### 6.3 Laya 输出协议与阈值

```json
{
  "schema_version": "1.0", "instruction_id": "I001",
  "label": "BUY",
  "prob": {"BUY": 0.82, "NO_BUY": 0.08, "HOLD": 0.09, "SELL": 0.01},
  "confidence": 0.82, "infer_ms": 34, "model_version": "laya-tickgold-v1"
}
```

- `BUY 且 prob ≥ 0.75` → 模拟盘执行；0.55–0.75 → 观察 + 灵动岛推送；<0.55 → 放弃本轮
  （下轮条件仍满足可重判，每指令每分钟最多 2 次，防抖）。
- 卖出独立通道：持仓股触发卖出条件后决策，重点判 SELL。
- 建议每战法独立微调实例或分类头（`laya-tickgold-leader / -1to2 / -dip`），共享权重。

### 6.4 Laya 部署绑定（Tauri Sidecar）

- Laya 作为**本地 HTTP 推理服务**（laya-cuda / laya-openvino；GPU ~33ms，CPU 80–150ms）。
- 设置中心新增「Laya 控制台」：检测安装 → 一键安装/启动/健康检查（`/health`）；
  TickGold 启动可选自动拉起。
- **降级**：Laya 不可用 → **纯规则模式**（条件满足即推灵动岛由人拍板），不阻塞盯盘，
  界面标注当前模式。
- **留痕**：决策包 + 输出 + 行情快照三方落 `decision_log`（毫秒时间戳），可回放、
  可追责。

### 6.5 异常边界

快照陈旧 >15s 不出决策；9:25 竞价沿用定格口径；14:55 后禁止新开仓（可配）；
本地模式零外发；云端模式明示外发内容。

## 七、第 5 步 · 执行层（模拟盘自主买卖 + 信号链）

在现有模拟交易（A 股规则/T+1/费用/持仓/流水）上新增**自动执行器**：

- **买入**：`BUY ≥ 阈值` → 仓位取 min(计划仓位, 可用资金允许, 单票上限, 总仓位上限)，
  100 股取整，实时对手价 + 滑点假设（默认 0.1%）虚拟成交；不足自动缩量并记原因。
- **卖出**：风控规则优先级最高——**硬止损（默认 -7%）命中无需 Laya 直接执行**；
  动态止盈/断板类条件结合 Laya SELL；T+1 校验沿用。
- **成交记录扩展**：`instruction_id / decision_log_id / label / prob / 触发规则 /
  买卖原因（模板生成，慢脑盘后润色）/ 决策包快照 / K线截图引用`。
- **界面**：流水标记「AI 自主/人工」与原因展开；账户总览新增 AI 模式开关与
  **一键急停**（停止全部自动开仓，仅保留卖出风控）。
- **实盘信号模式**：决策推灵动岛（条件+概率+一句话原因）→ 用户自行人工下单；
  未来 QMT/Ptrade（顺延 v2.3、合规前提）只能插在「风控闸门之后」，默认二次确认；
  预留 `BrokerGateway` trait。

## 八、第 6 步 · 回灌层（结果 → 标注 → 大脑升级）

### 8.1 T+N 结果归因与自动标注

- T+1 / T+3 / T+5 自动取行情结算每笔收益，关联决策包与因子值。
- 自动标注（避免人工偏差）：T+3 ≥ +5%（或涨停）→ BUY 正样本；≤ -5%（或止损）→
  NO_BUY 正样本；卖后继续大涨 → SELL 负样本；卖后大跌 → SELL 正样本。
- 慢脑对失败交易输出误判归因：规则问题 / Laya 概率问题 / 执行滑点 / 系统性风险，
  结论入复盘案例库。

### 8.2 两路升级

| 对象 | 方式 | 节奏 |
|---|---|---|
| 慢脑 / 向量库 | 每日案例（成功+失败）+ 周度总结入库；战法心得经用户确认沉淀 | 每日 |
| Laya 快脑 | 每战法累积 ≥500 标注样本 → 离线微调 → **影子模式 2 周**（只记不执行）→ 胜率与校准度优于现版才切换 | 月度批次 |

- **防退化**：全部模型版本保留 + 回测对照；新版影子/模拟盘的胜率、Brier 校准不达标
  拒绝上线，支持一键回滚。
- **防过拟合**：盘中禁止改参数/权重；样本按时间段切分（旧训练、近月验证）。
- **可见性**：每周《大脑进化周报》——样本量、胜率曲线、校准度、Top 误判案例、
  知识库更新条目。

### 8.3 闭环时间轴

```
T 日 20:00 计划待确认 → T+1 盯盘决策执行 → T+1 晚案例向量化
→ T+4 T+3 结算自动标注 → 月末微调 Laya → 影子 2 周 → 达标上线
```

## 十一、风险、红线与测试

1. **合规**：模拟盘全自动、实盘仅信号；界面保留「不构成投资建议」；研报/公告只存
   摘要 + 原文链接；不做投顾、不接代客理财。
2. **冷启动**：v2.1 初期无标注样本 → 规则触发与 Laya 影子打分并行（只记录不执行）；
   用本地历史快照回放批量造初始样本，每战法 ≥500 后再开自动执行。
3. **Laya 生态新**：HTTP 适配层隔离，服务故障自动降级纯规则，不影响盯盘。
4. **过拟合**：盘中禁改参数；新版必须影子对照 + Brier 校准达标 + 可回滚。
5. **资源**：慢脑/快脑均提供 CPU 模式（OpenVINO），慢脑可仅用云 Key。
6. **测试**：因子口径单测、决策包 schema 快照测试、Laya mock server、decision_log
   历史回放、模拟盘全自动干跑一周（干跑期只记录不成交或内部虚拟成交）。
7. **安全**：云 Key 本地加密；MCP 仅监听 127.0.0.1；本地模式零外发明示。

## 十二、明确不做（Out of Scope）

- 不接券商真实自动下单（QMT/Ptrade 为 v2.3 及以后，用户自有账户、合规前提下的可选项）；
- 不做确定性涨跌预测、目标价承诺；
- 不做 PDF/网页全文转载存储；
- 不在盘中允许 AI 修改计划、因子权重或模型版本；
- 不保证免费行情的实时性（3–5s 口径），毫秒级仅指模型推理。
