# 复盘时间线卡片 重新设计方案

> 日期：2026-01-15
> 状态：设计确认，待实现
> 版本：v1.0

## 一、背景与问题

### 1.1 现状问题

现有 `ReviewTimeline.vue` 复盘时间线卡片存在以下问题：

1. **功能定位偏差**：名为"复盘"，实际只做实时异动盯盘，非交易时间打开一片空白
2. **无历史回看能力**：只能看"今天"的实时数据，无法回看历史交易日
3. **数据来源单一**：仅依赖 `spider:events` 实时异动和 `radar:data` 雷达推送
4. **已知 Bug**：
   - 主力资金负数显示红色（应为绿色）
   - 引擎启动失败静默，用户无感知
   - 非交易时间空状态体验差

### 1.2 设计目标

将"实时异动面板"升级为**真正的复盘工具**：

- ✅ 盘后快速复盘：收盘后即可查看当日完整复盘
- ✅ 历史回看：任意交易日都能看复盘数据
- ✅ 实时模式保留：交易时间可切换到实时盯盘模式
- ✅ 渐进式展开：紧凑卡片不占地，展开后信息全

### 2.2 核心设计原则

1. **数据层与视图层分离**：`useReviewData` 统一封装两套数据源，UI 层不关心数据来源
2. **渐进式信息密度**：紧凑视图给核心信息，展开视图给完整信息
3. **自动模式切换**：根据交易时间智能选择默认模式，用户可手动覆盖
4. **复用现有能力**：最大化利用已有的数据接口，不重复造轮子

### 2.3 自动模式切换逻辑

| 当前状态 | 默认模式 | 手动切换 |
|---------|---------|---------|
| 交易时段（周一至周五 9:15-15:05） | 实时模式 | 可切到历史模式看之前的交易日 |
| 非交易时段 | 历史模式（最近交易日） | 实时模式按钮灰掉，提示"非交易时间" |

## 三、数据层设计：useReviewData

### 3.1 对外暴露的统一数据结构

```typescript
interface ReviewData {
  date: string;              // YYYYMMDD
  mode: 'history' | 'realtime';
  
  // 情绪数据
  emotion: {
    sentiment: number;       // 0-100 情绪温度
    mood: string;            // 冰点/低迷/中性/活跃/亢奋
    hist: number[];          // 情绪曲线历史数据点
    change: number;          // 较昨日变化
  };
  
  // 涨跌结构
  structure: {
    limitUp: number;         // 涨停数
    limitDown: number;       // 跌停数
    broken: number;          // 炸板数
    sealRate: number;        // 封板率 %
    upCount: number;         // 上涨家数
    downCount: number;       // 下跌家数
    mainFund: number;        // 主力资金净流入（亿）
    maxBoards: number;       // 最高连板数
    topStock: string;        // 最高连板股名称
    distribution: number[];  // 涨跌幅分布（10档）
  };
  
  // 时间线节点
  timeline: TimelineNode[];
  
  // 热点板块
  sectors: SectorRow[];
  
  // 龙头个股/连板梯队
  ladder: LadderGroup[];
  
  // 龙虎榜
  lhb: LhbStock[];
}

interface TimelineNode {
  time: number;              // 时间戳
  type: 'limit_up' | 'broken' | 'reseal' | 'lhb' | 'sector' | 'promote';
  code: string;
  name: string;
  title: string;             // 节点标题（如"首封涨停"）
  desc: string;              // 描述
  pct?: number;              // 涨跌幅
  tone: 'up' | 'down' | 'neutral';
  extra?: Record<string, any>;
}
```

### 3.2 历史模式数据构建逻辑

#### 时间线节点来源优先级

1. **涨停首封时间**：从 `fetchZtPool()` 的 `firstSeal` 字段提取
   - `broken === 0` → 类型 `limit_up`（首封涨停）
   - `broken > 0` → 类型 `reseal`（回封涨停）+ 额外记录炸板节点
2. **炸板时间**：从 `fetchZbPool()` 提取（如无时间则放到午盘时段）
3. **龙虎榜上榜**：从 `fetchLhbList()` 提取（时间标记为收盘后）
4. **板块异动**：从 `fetchSectors()` 涨幅前3板块（时间标记为全天）
5. **连板晋级**：对比昨日连板梯队计算（时间标记对应首封时间）

#### 情绪曲线构建（历史模式）

由于历史数据没有逐分钟情绪，用**时间段近似**：
- 早盘（9:30）：根据开盘涨跌比估算
- 午盘（11:30）：上午收盘数据
- 午后（13:30）：午后开盘数据
- 收盘（15:00）：最终数据
- 用插值算法填充中间点，形成平滑曲线

### 3.3 实时模式

直接复用现有 `useMarketFeeds` 的 `radar` 和 `events` 数据，转换为统一格式即可。

## 五、模块详细设计

### 5.1 时间线模块（核心）

#### 节点类型与颜色

| 类型 | 图标/颜色 | 来源 |
|------|----------|------|
| 首封涨停 | 红圆 | 涨停池 firstSeal，broken=0 |
| 炸板 | 橙圆 | 炸板池 / 涨停池 broken>0 |
| 回封涨停 | 金圆 | 涨停池 firstSeal，broken>0 |
| 龙虎榜上榜 | 蓝圆 | 龙虎榜列表 |
| 板块异动 | 绿圆 | 板块涨幅前3 |
| 连板晋级 | 紫圆 | 连板梯队计算 |

#### 时间分组

按时间段分组，每组可折叠/展开：
- **早盘**（9:25-10:30）— 默认展开，开盘半小时最关键
- **午前**（10:30-11:30）— 默认展开
- **午后**（13:00-14:00）— 默认展开
- **尾盘**（14:00-15:00）— 默认展开，收盘前半小时关键

#### 交互

- **点击节点**：高亮显示，右侧联动（如有详情）
- **hover 节点**：显示 tooltip（封单金额、换手率、所属板块等）
- **过滤按钮**：顶部快捷过滤，可勾选显示哪些类型节点

### 5.2 情绪曲线模块

| 视图 | 展示形式 |
|------|---------|
| 紧凑视图 | 圆形仪表盘 + 情绪等级文字 + 较昨日变化 |
| 展开视图 | 面积折线图 + 关键时间标注（开盘/午盘/收盘） |

**仪表盘颜色**：
- 0-20：冰点（深绿 #1a5f46）
- 20-40：低迷（浅绿 #3ba776）
- 40-60：中性（黄 #e3b341）
- 60-80：活跃（橙 #f0883e）
- 80-100：亢奋（红 #e0455a）

### 5.3 涨跌结构模块

**顶部 4 个核心指标**（一行）：
- 涨停数（红）
- 跌停数（绿）
- 炸板数（橙）
- 封板率（%）

**下方 3 行**（宽行）：
- 上涨 / 下跌 家数比
- 主力资金净流入（亿）— **正数红、负数绿（修复现有bug）**
- 最高连板数 + 龙头股名称

### 5.4 热点板块模块

- 表格形式，显示前 10 名板块
- 列：排名 / 板块名称 / 涨跌幅 / 主力净流入 / 领涨股
- 默认按主力净流入排序，可点击表头切换排序
- 数据来源：行业 + 概念板块合并去重，取涨跌幅绝对值更大的

### 5.5 龙头个股 / 连板梯队模块

- 按连板数从高到低排列
- 每行：连板数标签 + 个股名称 + 涨幅
- 最高板用金色高亮
- 首封时间质量染色：
  - 10:00前 → 金色（早盘强板）
  - 14:30后 → 灰色（尾盘偷袭板）
  - 炸过板 → 橙色警示
- 首板数量多，默认只显示前 10，点击"展开全部"显示完整列表

### 5.6 龙虎榜模块

- 精简列表，显示前 10 只上榜个股
- 每行：个股名称 / 涨幅 / 净买入金额 / 上榜原因
- 分类标签：🐙 知名游资 / 🏛️ 机构 / 💴 北向
- 点击个股 → 弹出买卖前五席位详情（可选，v1.1做）

## 六、状态设计

### 6.1 加载状态

- 骨架屏占位，各模块独立 loading
- 先加载核心数据（涨跌结构），再加载时间线等非核心数据

### 6.2 空状态

- **无数据**：友好提示 "该日期暂无复盘数据" + 一键切换到最近有数据的日期
- **非交易时间实时模式**：显示 "当前非交易时间，已自动切换到历史模式"
- **引擎启动失败**：显示错误提示 + 重试按钮（修复现有静默失败bug）

### 6.3 错误处理

- 单个模块加载失败不影响其他模块
- 失败模块显示错误提示 + 重试按钮
- 核心数据全失败时显示全局重试
