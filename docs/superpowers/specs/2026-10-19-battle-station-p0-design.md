# 作战台 2.0 · P0 设计（时间轴 + 下单条）

> 状态：设计待评审　|　日期：2026-10-19　|　基线版本：TickGold v3.11.1
> 上游设计：[AI 智能化交易系统 · 双脑闭环设计](2026-09-30-ai-trading-pipeline-design.md)（本文不改变双脑与六步引擎，只重做用户入口）

## 一、背景

「今日作战流」当前是六步任务清单（采集 → 分析 → 计划 → 盯盘 → 执行 → 回灌），每步一个按钮、严格门禁；「一键智驾」是模拟盘全自动；实盘走「信号确认桥 → 生成下单文本 → 复制 → 切同花顺粘贴」。三者并存，导致：

1. **节奏错位**：短线的主战场是 9:15–10:00，而六步是「做完一步点下一步」，没有时间轴。
2. **入口错位**：交易工具 25 个按数据源分组，用户不知道「现在该开哪个」。
3. **执行摩擦**：实盘从信号到下单要跨 3 个界面、复制粘贴，开盘几分钟内来不及。
4. **反馈断链**：回灌只产出统计，不回写次日作战卡。

已确认的三条边界：

| 决策 | 结论 |
|---|---|
| 自动化 | **双轨**：模拟盘全自动；实盘一键确认 |
| P0 范围 | **只做时间轴 + 下单条**，不做指令状态机/触发引擎/AI Copilot |
| 时段划分 | 以**开盘期间**为核心，其它时段粗粒度 |
| 实盘确认 | **一次确认**（单个确认弹窗，不二次输入） |

## 二、目标与非目标

**P0 目标**

1. 打开应用 1 秒内知道「现在处于哪个时段、该做什么」。
2. 任意时刻可在当前卡片内完成一笔下单：**≤3 次点击**（选代码 → 买/卖 → 确认）。
3. 模拟/实盘双轨清晰，实盘一次确认、默认关闭、全程走既有风控闸门。
4. 六步引擎原样保留在后台，旧流程可回退。

**非目标（P0 不做）**

- 指令状态机、条件触发引擎（P1）
- 自动盘后流水线触发、命中率回写（P1）
- AI Copilot 自然语言下单（P3）
- 菜单分组重构、快捷键全量（P2）
- 任何券商底层、风控参数、双脑模型的改动

## 三、时间轴设计

### 3.1 时段模型（北京时间，纯函数可测）

| 阶段 | 时间 | 子阶段 | 作战台主信息 |
|---|---|---|---|
| 盘前 | 08:30–09:15 | — | 昨日复盘结论、今日作战卡前 3 条、账户条 |
| 集合竞价 | 09:15–09:30 | 09:15 可委托 / **09:20 不可撤单** / 09:25 开盘价 | 计划股竞价表现、撤单/改价入口 |
| **开盘** | **09:30–10:00** | 09:30–09:35 首波 / 09:35–09:45 承接 / 09:45–10:00 分歧 | 计划股实时涨幅、触发候选、下单条 |
| 盘中 | 10:00–14:30 | — | 持仓盈亏、止损预警、今日成交 |
| 尾盘 | 14:30–15:00 | — | 持仓过夜评分、尾盘强度 |
| 盘后 | 15:00–次日 08:30 | — | 今日战果、明日作战卡、一键跑盘后流水线 |

边界约定：09:25–09:30 归入「集合竞价」并显示「等待开盘」；15:00 后归入「盘后」直到次日 08:30；周末/节假日统一显示「休市 · 下一交易日倒计时」（复用现有交易日判断，不做节假日库）。

### 3.2 非线性时间轴（开盘占一半视觉宽度）

- 轨道总宽 100%：`集合竞价+开盘（09:15–10:00）占 46%`，其余时段合计 54%。
- 开盘段内再按 5/10/15 分钟比例画三个子刻度，10:00 之后恢复线性。
- 当前阶段高亮 + 阶段内进度条 + 「距下一阶段 12:34」倒计时（1s 刷新）。
- 时间轴点击任意阶段可预览该阶段清单（不改变当前状态）。

### 3.3 每阶段「现在该做」清单（复用现有数据，不新增后端）

- 盘前：`workflow.feedback.conclusion`（昨日结论）、`workflow.battlePlan.instructions.slice(0,3)`、账户条（复用 `brokerGetStatus`）。
- 竞价：计划股代码 + 实时涨跌幅（`quotes` store）、09:20 不可撤单提示。
- 开盘：计划股实时涨幅排序、涨速前 3、一键把代码送进下单条。
- 盘中：`execStatus` 信号/成交数、持仓浮盈（`riskSnapshot`）。
- 尾盘：持仓列表 + 过夜提示。
- 盘后：`feedback` 四项统计（信号/成交/已实现盈亏/胜率）+「跑盘后流水线」按钮（复用 `workflow.runAfterClosePipeline`）。

## 四、下单条设计

### 4.1 位置与形态

- 只存在于作战台卡片内部，固定在卡片底部，高度 56px，不遮挡其它卡片。
- 单行布局：`[代码+名称+最新价] [价格 5 个快捷 chips] [数量+仓位档] [买入] [卖出] [撤单] [模式徽标]`
- 价格 chips：最新 / 买一 / 卖一 / 涨停 / 跌停；点选即填入，可手改。
- 数量：手数输入 + 仓位档（1/2、1/3、1/4，按可用资金换算并取整 100 股）。
- 模式徽标：`模拟`（绿）/`实盘`（红）；实盘需在券商设置里已开启，否则徽标显示「实盘未启用」。

### 4.2 一次确认弹窗

点击买入/卖出后弹出唯一确认框，展示并只展示以下字段：

```
方向  买入  ·  贵州茅台 600519
价格  1780.00（买一）   数量 100 股（1/2 仓）
金额  178,000 元        账户  实盘 · 同花顺
风控  提交时校验（熔断 / 白名单 / 单笔上限 / 新鲜度）
[取消]                    [确认下单]
```

- 确认按钮是唯一动作，点击即提交；不做二次输入/长按。
- 风控不在前端重复实现：提交后由 `submit_with_sig` 统一裁决，失败原因原文回显在弹窗内，用户可改价/改量重试。
- `kill_switch` 生效时整条下单条置灰，提示「已熔断」。

### 4.3 双轨行为

| 模式 | 提交路径 | 结果反馈 |
|---|---|---|
| 模拟 | `broker_quick_order` → `submit_with_sig`（mock 分支）→ 模拟账本 | 成交 toast + 持仓/成交刷新 |
| 实盘 | `broker_quick_order` → `submit_with_sig`（client/qmt 分支）→ sidecar | 下单截图 + 订单状态回写 + 失败原因 toast |

两条路径共用同一命令与同一套闸门（kill switch、连接态、频率熔断、白名单、单笔上限、新鲜度、涨跌停、T+1、仓位），**不新增任何绕过风控的入口**。

## 五、技术设计

### 5.1 前端

新增 `src/components/battle/`：

| 文件 | 职责 |
|---|---|
| `BattleStation.vue` | 卡片壳：账户条 + 时间轴 + 阶段面板 + 下单条；替代 `Cockpit.vue` 作为 `cockpit` 卡片内容 |
| `PhaseTimeline.vue` | 时段模型渲染、倒计时、子刻度、点击预览 |
| `PhasePanel.vue` | 当前阶段「现在该做」清单，复用 workflow/quotes/risk 数据 |
| `OrderDock.vue` | 下单条 + 确认弹窗 + 提交与结果处理 |
| `useBattlePhase.ts` | 纯函数 `computePhase(now)`、`nextBoundary()`、`phaseProgress()`（vitest 单测） |

保留 `Cockpit.vue` 不删除，卡片右上角提供「旧版六步 / 新版作战台」切换按钮（localStorage `battle_station_v2`，默认 `on`）。

### 5.2 后端

`src-tauri/src/broker/mod.rs` 新增：

```rust
#[tauri::command]
pub async fn broker_quick_order(
    app: AppHandle,
    code: String,
    side: String,          // "BUY" | "SELL"
    price: f64,
    vol: i64,
    position: Option<i64>, // 仓位档，仅用于审计留痕
) -> Result<protocol::BrokerOrderInfo, String>
```

实现步骤：

1. 校验：6 位代码、side 合法、price>0、vol>0（买入按 100 股取整）。
2. 取名：`market::get_quotes([code])`，失败则用代码占位。
3. 建单：复用 `ai::bridge`，新增 `create_confirmed_ticket(conn, input, price, vol)`——内部沿用 `create_ticket` 的字段与同日同向去重，写入后立即置 `status='confirmed'`（`source='dock'`、`reason='下单条手动下单'`），返回 `sig_id`。
4. 提交：调用既有 `submit_with_sig(&app, &sig_id)`，返回订单信息。
5. 失败：把该票据置 `rejected`（保留审计），原样返回闸门文案。

前端 API：`src/broker/api.ts` 增加 `brokerQuickOrder(...)`。

### 5.3 数据流

```
用户输入 → OrderDock 本地校验（代码/价格/数量/金额）→ 确认弹窗
        → invoke broker_quick_order
        → signal_ticket(confirmed) → submit_with_sig
        → 闸门（kill/连接/频率/白名单/金额/新鲜度/涨跌停/仓位）
        → mock: portfolio::apply_fill   |  client: sidecar 闪电下单
        → 事件 broker:order_update / broker:client_shot
        → OrderDock toast + 订单列表刷新 + 时间轴「今日成交」数字 +1
```

### 5.4 错误处理

- 未连接/未登录：确认弹窗禁用，提示「先连接券商」并提供跳转。
- 风控拒绝：弹窗内展示原文（如「标的不在实盘白名单」），不关闭弹窗，用户可改价改量重试。
- 下单超时：`submit_with_sig` 返回错误后展示，并在订单列表标红该笔；不自动重试。
- 时钟异常（系统时间与交易时段不符）：时间轴显示「时间未校准」，下单条仍可用但提示核对。

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 09:31 打开应用 | 「开盘」阶段 1s 内高亮，子阶段与倒计时正确 |
| 2 | 模拟盘下单 | 选代码 → 买入 → 确认，3 次点击完成，模拟账本出现成交 |

| 7 | 旧流程回退 | 设置切换「六步流程（旧）」后，原 Cockpit 完整可用 |
| 8 | 时段边界 | 08:59/09:15/09:20/09:25/09:30/10:00/14:30/15:00 单测全部通过 |

## 七、后续阶段（P0 之后）

| 阶段 | 周期 | 内容 | 验收 |
|---|---|---|---|
| P1 计划即执行 | 2 周 | 指令状态机（待触发/已触发/已下单/已成交/已放弃）、触发引擎（价格/涨幅/量比/时间窗）、计划 → 预警 → 触发 → 一键下单（模拟自动、实盘提示）、15:05 盘后流水线、作战卡命中率 | 次日无需再点采集/分析/计划；触发延迟 <2s |

| P3 智能与进化 | 3 周 | AI Copilot（自然语言 → 条件单/预警）、盘口分时联动、六战法参数模板、指令级打标 → 次日权重、多账户 | 盘前确认 <2 分钟；20 日滚动胜率可解释 |

## 八、指标

- 打开应用到完成一笔下单：**≤3 点击、≤5s**（P0 先看模拟盘）。
- 盘前作战卡确认：**≤2 分钟**。
- 阶段切换误差：**≤1s**。
- 下单失败可解释率：100%（失败必给原文原因）。
- 盘前/盘中打开率、作战台停留时长（P1 起统计）。

## 九、风险与边界

1. **误触实盘**：默认模拟、实盘需先在设置启用、红色徽标、单次确认、熔断置灰；确认弹窗展示金额与账户类型。
2. **时段判断依赖本机时钟**：统一用 `Asia/Shanghai` 时区计算，系统时区不符时提示校准。
3. **下单条遮挡**：仅在作战台卡片内固定，不进入全局浮动层。
4. **合规**：保持「模拟优先、实盘人工确认、不代客、不改客户端」；确认弹窗常驻风险提示一行。
5. **回退**：`battle_station_v2` 开关可一键切回六步旧流程。
