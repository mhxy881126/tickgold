问题分级总览

52 个证据条目（部分条目含多个子问题）· P0 6 / P1 9 / P2 37
P0-1
发版后真机验证缺失，且无回滚预案（当前最高风险）
CI 全绿替代不了真机签收；同花顺通道无法被 Vitest / cargo / Playwright 覆盖。
P0-2 · B-01
闪电下单限价被静默丢弃，风控价与真实成交价脱钩
Python 只填数量不填价，按客户端盘口价成交，风控仍按被丢弃的参考价计算。
P0-3 · B-03
单笔撤单假成功、急停对 client 通道非真撤
只打开撤单页即回报 cancelled，券商侧委托可能仍存活成孤儿在途单。
P0-4
sidecar 无操作看门狗 / 串行队列 / 断连重建，链路可能假活
GUI 卡死全链排队持锁；心跳盲发，xiadan 死亡而 connected 仍为 true。
P0-5 · F-01
急停零确认、三口径
驾驶舱零确认 / 风险卡 confirmDialog / 灵动岛 window.confirm，同一动作三种行为。
P0-6
查询失败 / 空结果语义混淆（缺显式 ok:false）
Rust 遇非空 note 一律按失败帧丢缓存，空结果被误判为失败。

P0-2新发现 B-01→ v3.14

闪电下单价格真实送达：限价不得被静默丢弃

Python 闪电流程只填数量从不填价，实际按客户端盘口价成交；风控却用被丢弃的参考价算涨停/单笔/单日。处置：完整输入价格，或读回客户端真实价重算风控，确认单标注「盘口价/限价」。
sidecar_client.py:1570（只填数量）:1583（自认盘口价）risk.rs:181-184（涨停）mod.rs:1837-1838（单笔）mod.rs:1848-1849（单日）
P0-3新发现 B-03→ v3.14

真实撤单：读回挂单表确认消失才落 CANCELLED

do_cancel 仅 F5/F3 打开撤单页就 emit cancelled，本地落 CANCELLED 而券商侧委托可能仍存活。拆出 cancel_page_opened / cancelled 两态；急停对 client 通道做真实撤买撤卖 + 读回确认。
sidecar_client.py:1764-1780:1765（无单笔精确撤单）:1779（直接 emit cancelled）mod.rs:2192-2207mod.rs:2431-2459（急停）
P0-4→ v3.14（旧 P0-2，仍开放）

看门狗 / 串行队列 / 断连重建：链路不得假活

单 GUI 操作硬超时（建议 10s）→ 判定卡死 → 断连 → 重建执行线程、退休卡死线程 → 后续快速失败；单一 OperationQueue；心跳带存活判定；人工等待移出全局锁。
sidecar_client.py:740（30s 锁）:2311-2318（每方法新建线程）:303-306（心跳盲发）sidecar.rs:168-195（无重连）
P0-5新发现 F-01→ v3.14（安全相关先做）

统一急停确认：三处入口共用同一段风险文案与组件

确认下沉到 store 的 emergencyHalt / 统一 executeHalt() 门面；确认框列出后果清单（封新委托、撤 N 条件单、撤 M 在途、断 sidecar）；急停后全屏 chip + 解除路径（解除同样需确认）。
Cockpit.vue:227-229（零确认）RiskDashboard.vue:230-238Island.vue:218（window.confirm）workflow.ts:971（无确认）
P0-6→ v3.14（旧 P0-3，更严重）

ok:false 失败语义：失败绝不覆盖缓存、绝不参与对账

统一查询协议 {ok:bool, data, note, ts}：ok:false = 读取失败，保留缓存；ok:true + 空数组 = 真实空数据，正常清缓存。前端区分「空仓/无挂单」与「读取失败（点重试）」；HTTP 端点失败不返回 success。
