## 一、问题

旧实现用「帧里是否带 `note`」作为读取失败启发式：

- THS trades 成功但当日无成交时发 `note="当日暂无成交记录"`，pending 成功但无挂单时发 `note="当前无挂单"`；
  Rust 一见 `note` 就当失败帧处理 → 把「成功为空」误判成「读取失败」。
- 失败帧与「空仓/无成交/无挂单」成功帧在协议层无法区分，前端只能靠 `note && !数据键` 猜，
  失败时还可能被清空列表，伪装成「暂无」。

P0-6 改为显式 `ok: bool` 标志：`ok:false` 才是读取失败（数据键为空 + 明确失败原因），
`ok:true`（含空列表）是成功；缺 `ok` 的旧帧（QMT / 旧 sidecar）按成功处理，向后兼容。

### 4. 前端 `src/components/BrokerConsole.vue`

四个加载函数由 `note && !数据键` 启发式改为显式 `ok === false` 判定：

- loadAsset 158-173：`ok===false` → 保留上次成功资产、仅 `queryErr=note` 后 return，不覆盖；
  「正在向客户端查询…」进行中提示不误清错；成功帧解除错误并回填。
- loadPositions 174-189：`ok===false` → 保留既有持仓列表、仅显错误；成功（含空仓）`positions=??[]` 替换并清错。
- loadTrades 190-206：`ok===false` → 保留既有成交列表、仅显错误，不清空伪装「暂无成交」；
  成功非空替换、成功为空（`trades:[]`）清空并清错。
- loadPending 207-219：同 trades，`ok===false` 保留挂单列表、仅显错误。
- 事件监听按 ok 区分：`broker:trades` 647-659、`broker:pending` 660-672；
  `ok===false` 保留列表只显错误，`数据键 !== undefined` 的成功帧（含空列表）替换并清错。
- 三态空态文案沿用既有 870（持仓）/897（成交）/919（挂单）：`queryErr ? "读取失败，请点「刷新」重试" : "暂无X"`，未改模板。

三态定义：成功非空→替换列表；成功为空→清空列表并解除 queryErr；读取失败(ok:false)→保留既有列表、显示读取失败 + note。
