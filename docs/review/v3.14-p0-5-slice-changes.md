## 五、Ctrl+Alt+K 全局快捷键：保持零确认，未加任何阻塞式确认

定位结论（已实读，本切片未改 Rust）：

- 该快捷键**不在**前端 useActions action 注册表 / keymap / 前端 keydown 里，而是 Rust 侧 `tauri_plugin_global_shortcut` 注册：
  `src-tauri/src/setup.rs:178` `gsc.on_shortcut("Ctrl+Alt+K", …)`，Pressed 时 `spawn` 直接 `broker::emergency_halt(&h).await`（setup.rs:182），失败仅 `log::error!`。
- 口径核对：invoke 命令 `broker_emergency_halt`（`src-tauri/src/broker/mod.rs:2520-2521`）就是委托给同一个 `emergency_halt(&app).await`；
  Rust 快捷键调的也是同一个 `broker::emergency_halt`；二者都走 mod.rs:2408 的同一函数，成功后都 `emit("risk:halted", {coCount, orderCount})`（mod.rs:2514）。
  → 快捷键与界面按钮**同底层、同事件口径**，不存在绕开统一路径，因此**无需接线改动**。
- 处理方式：**保持即时触发、绝不给它加阻塞式确认框**；前端 `emergencyHalt()` 确认路径与快捷键互不经过（快捷键在 Rust 直调，不进前端 `confirmEmergencyHalt`）。

**待决策项（本切片不擅自改）**：Ctrl+Alt+K 是否需要「轻量确认」（如长按 0.5s / 二次按压 / 顶部一次性 toast 提示）？当前按刻意设计保持零确认紧急逃生，是否保留交由产品决策；本切片只把界面三入口的确认口径统一，不改动快捷键语义。

## 六、Island 独立 Webview 无 AppDialog 宿主风险（关键真机验证点）

事实（`src/main.ts:52-56`）：`label === "island"` 的窗口 `createApp(Island).mount("#app")`，**不挂 App.vue，也就没有 `<AppDialog />` 宿主**；
ToastContainer 同样只在主窗口 App.vue。若在岛窗直接调 `confirmDialog()`，其 Promise 无人 resolve → 点击后永久挂起（这正是旧版 Island 用原生 confirm 的原因）。

不破坏现状的处理（已落地）：
- `AppDialog.vue:5` import、`52-56` onMounted 调 `markDialogHostMounted(true)`，登记本 Webview 已有宿主。
- `confirmEmergencyHalt()`：**有宿主** → `confirmDialog(EMERGENCY_HALT_DIALOG)`（danger 红）；**无宿主（岛窗）** → 回退 `window.confirm`，文案与共享常量完全一致；无 window 环境直接返回 false，不抛错、不挂起。
- 代价（需知晓）：岛窗原生 confirm 无法渲染 danger 红，属岛窗尺寸/透明边框现状约束，未为它新造组件。
