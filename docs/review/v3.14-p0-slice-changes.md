## 一、P0-2　闪电/市价丢价脱钩

**问题**：键盘精灵 21/23 闪电弹窗只填数量、不填限价（`sidecar_client.py` do_submit 只 `input_id(CID_ORDER_AMT, vol)`），下发参考价被静默丢弃、实际按客户端盘口价成交；但 Rust 仍按被丢弃的参考价算单笔/单日金额上限与涨停拦截，风控价与真实成交价脱钩。

**修法（选定方案：盘口通道不拿被丢弃限价做权威金额风控，改用行情快照最坏边界重算）**：

1. `src-tauri/src/broker/risk.rs`
   - 新增纯函数 `market_order_amount_bound(side, vol, market) -> Option<f64>`（risk.rs:369-383）：BUY → `limit_up × vol`（买入最坏成本）；SELL → `limit_down × vol`（卖出最坏回款）；所需涨跌停价缺失 / 方向非法 → `None`，由调用方 fail-safe 拒绝。
   - 参考价涨跌停反向拦截（risk.rs:178-194）逻辑原样保留，仅补注释：对盘口通道该拦截属保守/建议性，权威暴露上限以快照最坏边界为准，不得削弱。
   - 未改 `RiskOrder` 结构体、未改 `check()` 签名（避免牵动大量既有测试字面量）。
2. `src-tauri/src/broker/mod.rs`（is_live 块，1837-1859）
   - 仅当 `cfg.kind == "client"`（闪电盘口通道）时，单笔上限与单日 BUY 累计改用 `risk::market_order_amount_bound(&side, vol, market)`；bound 为 `None` → fail-safe 拒绝，文案「行情未就绪，无法按盘口价估算金额上限，请稍后重试」。
   - `mock` / `qmt` 分支保持原 `price*vol` 计算不变（else 分支）。
   - 上游 1826 `limit_prices_ready` 已要求涨跌停双全，bound 实际不会为 None；None 分支属纵深 fail-safe。
3. `src-tauri/resources/broker/sidecar_client.py`
   - 闪电单 screenshot expect 增加 `"fillMode": "market"`（do_submit，约 1633），message 改为「按客户端盘口价成交（fillMode=market），金额为参考估算、以成交回报为准」（约 1636）。
   - `pre_check` live_guarded 白名单/单笔/单日拦截逻辑保留为次级兜底，仅文案改「参考估算」（205-216），白名单仍是硬拦截。
   - 新增纯函数 `order_amount_is_authoritative(p)`（718-721）：仅限价（limit/缺省）产生权威金额，market 不产生。

## 二、P0-3　撤单假成功

**问题**：THS `do_cancel` 只 F5/F3 打开撤单页就 `emit status:"cancelled"`，Rust/急停据此本地落 CANCELLED，券商侧委托可能仍存活成孤儿单。

**修法（撤单后读回挂单表确认消失才上报 cancelled；仍在/读回失败上报非终态，绝不本地落 CANCELLED，留待对账）**：

1. `sidecar_client.py` 新增纯函数 `classify_cancel_readback(target, pending) -> (status, note)`（675-715）：
   - `pending is None`（读回失败）→ `cancel_opened`；
   - 按 code+side+vol 命中且仍在（price 仅 ±1% 软匹配，不参与硬判定）→ `cancel_pending`；
   - 无命中（目标消失）→ `cancelled`；
   - 目标标识不足（缺 code/side/vol）→ fail-safe `cancel_opened`，绝不报 cancelled。
2. THS `do_cancel`（1817-1854）：F5/F3 后复用委托查询读表模式（`read_table_uia` → 失败 `_copy_with_captcha` → `parse_tabular_data(required_headers=("证券代码",))` → `normalize_pending`），调用 `classify_cancel_readback`；仅 `cancelled` 才发 cancelled 事件，其余发非终态 status + note。
3. Rust 不改：非终态在 mod.rs 事件映射（535 `_ => return`）被忽略，委托保持 submitted，交对账处理。
4. `emergency_halt` 本地 CANCELLED 标记（mod.rs:2447-2459）本切片**未改**，列为后续项；DryRun `do_cancel`（442-446）原样未动。
